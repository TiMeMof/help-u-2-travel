# 路线规划指南

## 路线几何提取（重要）

地图上要画**真实路线**而不是两点直线，所有驾车/公交路线都必须提取完整几何：

- `maps_direction_driving` 返回 `route.paths[].steps[].polyline`，格式为 `"lng,lat;lng,lat;..."` 字符串。
- 解析方法：按 `;` 拆分每个点，再按 `,` 拆分经纬度，注意是 **lng 在前 lat 在后**，转换成 `[lat, lng]` 并按 steps 顺序拼接（相邻 step 首尾点重复时去重）。
- 存入数据的 `polyline` 字段：`[[lat,lng], [lat,lng], ...]`。
- 城际路线存 `intercity_routes[].polyline`；城内当天路线存 `daily_plan[].route`（数组，每段一个 leg：`{"from": "...", "to": "...", "mode": "自驾", "polyline": [[lat,lng],...]}`）。
- 公交路线 `maps_direction_transit_integrate` 的 walking/bus 段同理提取。

**坐标系**：高德返回 GCJ-02 坐标，原样写入即可，模板自动转 WGS-84 匹配 OSM 底图。不要手工纠偏。

**禁止编造**：坐标和 polyline 只能来自高德 API 真实返回。手工估算的坐标会偏移数公里，路线画出来对不上真实道路（曾出现过整镇点位偏 7km 的事故）。POI 搜索时注意限定 `city` 为目标区县，否则可能搜到同名地点（如"鱼味馆"搜到杭州市区店）。搜索不到的点位直接从方案删除或换点，不要硬编。

## 城际路线

### 自驾
- 用 `maps_geo` 将城市名转经纬度，再调 `maps_direction_driving`。
- 关注：总里程、预计耗时（含路况）、途经高速、服务区数量。
- 单日纯驾驶 ≤6 小时，超过则拆分为两天或增加中途停留城市。
- 新能源车：每 200-300km 标记一个充电点，用 `maps_text_search` 搜"高速服务区 充电桩"。

### 高铁/飞机
- 用通用搜索查"出发地 到 目的地 高铁/飞机 时长 班次"。
- 标注：大致耗时、班次密度、是否需要提前购票。
- 声明：班次为参考，需用户自行确认实时信息。

### 混合
- 城际段用高铁/飞机，城内段用打车/地铁/租车。
- 在行程中明确标注每段的交通方式和衔接点（车站/机场到酒店的交通）。

## 城内行程

### 景点排序原则
1. 按地理位置聚类，同区域景点放在同一天。
2. 开放时间早的景点放上午，夜市/夜景放晚上。
3. 热门景点建议工作日或一早前往，避开人流。

### 景点间交通
- 步行可达（≤1km）：标注步行，鼓励步行。
- 1-5km：提供打车（耗时+预估费用）和公共交通选项。
- 5km 以上：优先地铁（如有），其次打车。
- 用 `maps_direction_transit_integrate` 获取公共交通方案，用 `maps_direction_driving` 获取打车/自驾方案。

### 时间分配
- 每个景点标注建议游玩时长（从搜索结果获取，常见：博物馆 2-3h，公园 1-2h，古镇 3-4h，山岳 4-6h）。
- 景点间交通时间单独列出，不要混入游玩时长。
- 每日总活动时间（含交通）≤10 小时，留出用餐和休息。

## 时间轴自检清单

生成 daily_plan 后逐项核对：
1. 每项开始时间 = 上一项开始时间 + 上一项耗时（累进计算，不要拍脑袋写时间）。
2. 无时间倒流、无重叠。
3. `attraction` / `lunch` / `dinner` 项都带 `lat`/`lng`（地图按天编号串联依赖它）。
4. 每日总活动时长 ≤10 小时。
（`html_generator.py` 会自动校验 1-3 并告警）
